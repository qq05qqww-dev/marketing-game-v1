# Multi Game Platform V2.3 第 77 批
# 多遊戲新增模板說明檔 game_template_guide.txt 版

## 一、這份文件目的

這份文件用來定義：

以後新增一個新遊戲時，不要再重新做整套前台、後台、抽獎紀錄、結果彈窗、分享、領獎提醒。

正確方式是：

新增遊戲 = 新增玩法元件 + 註冊 gameType + 套用共用元件 + 接入共用抽獎流程

---

## 二、目前已建立的共用基礎

### 1. 遊戲註冊表

檔案位置：

frontend/src/games/gameRegistry.js

用途：

- 統一管理 gameType

## 四、新增一個遊戲的標準流程

假設要新增：

WHEEL 幸運輪盤

標準流程如下：

### 第 1 步：確認 gameRegistry.js 是否已註冊

檢查：

frontend/src/games/gameRegistry.js

確認有：

GAME_TYPES.WHEEL

以及：

GAME_REGISTRY[GAME_TYPES.WHEEL]

內容至少包含：

- gameType
- label
- shortLabel
- description
- icon
- frontPath
- adminPath
- boardComponent
- defaultRouteName
- defaultRequireSerialCode
- supportsSerialCode
- supportsShareBonus
- supportsSourceTracking
- supportsPrizeWeight
- supportsStock
- supportsRewardRecord
- status
- theme
- defaultConfig

---

### 第 2 步：建立玩法元件

建立資料夾：

frontend/src/views/games/playboards/

建立檔案：

frontend/src/views/games/playboards/LuckyWheelPlayBoard.vue

這個元件只負責輪盤玩法：

- 輪盤扇形
- 指針
- 旋轉動畫
- 停止位置
- 點擊開始
- 動畫結束後通知外層顯示結果

不負責：

- 活動資料
- 獎品展示
- 結果彈窗
- 抽獎紀錄
- 分享加次數
- 領獎提醒

這些都交給共用元件。

---

### 第 3 步：建立遊戲頁 View

建立：

frontend/src/views/games/WheelGameView.vue

或未來統一成：

frontend/src/views/games/GamePlayView.vue

理想上新遊戲頁應該使用：

- GameShell
- GameActivityHeader
- GameStatusNotice
- GameChanceCard
- GamePrizeShowcase
- GameRulesPanel
- GameResultModal
- GameDrawLogs
- GameClaimInfo
- GameQuickNav
- GameFooterInfo

中間玩法區放：

LuckyWheelPlayBoard

---

### 第 4 步：接入共用活動核心

在新遊戲頁使用：

useGameActivityCore.js

用途：

- 讀取 tenantSlug
- 設定 gameType
- 套用 campaign
- 套用 prizes
- 判斷活動狀態
- 計算可抽獎品
- 顯示活動同步時間

---

### 第 5 步：接入共用抽獎流程

在新遊戲頁使用：

useGameDrawEngine.js

用途：

- 抽獎中狀態
- 呼叫 draw API
- 標準化抽獎結果
- 更新剩餘次數
- 顯示結果彈窗

---

### 第 6 步：新增路由

在 router 加入類似：

/play/:tenantSlug/wheel

或未來改成統一路由：

/play/:tenantSlug/:gamePath

若使用統一路由，需要從 gameRegistry.js 找對應 gameType。

---

### 第 7 步：確認後端 Campaign gameType

資料庫 Campaign 要有：

gameType = WHEEL

並且此 Campaign 要屬於某個 tenant。

---

### 第 8 步：確認獎品資料

Prize 必須綁定：

- tenantId
- campaignId
- gameType 或透過 campaign.gameType 判斷

獎品欄位要走共用格式：

- title
- shortName
- icon
- imageUrl
- type
- probability / weight
- remainStock / quantity
- status

---

### 第 9 步：確認抽獎 API

所有遊戲都應該走同一套抽獎 API：

POST /api/draw-engine/campaigns/:campaignId/play

傳入：

{
  gameType: "WHEEL",
  source: "line",
  requireSerialCode: false,
  serialCode: ""
}

回傳統一格式後，由 useGameDrawEngine.js 標準化。

---

### 第 10 步：測試前台完整流程

測試：

1. 前台網址可開啟
2. 商家活動資料正確
3. 獎品展示正確
4. 抽獎機會正確
5. 點擊玩法元件可開始動畫
6. 動畫結束後顯示結果彈窗
7. 抽獎紀錄新增
8. 分享增加機會
9. 領獎提醒正常
10. 底部活動資訊正常
11. 手機版正常
12. 桌機版正常

---

## 五、新增遊戲最少需要的檔案

以 WHEEL 為例，最少需要：

1. frontend/src/views/games/playboards/LuckyWheelPlayBoard.vue
2. frontend/src/views/games/WheelGameView.vue
3. router/index.js 新增 route
4. backend 補建 WHEEL campaign 的 patch script 或後台建立活動
5. gameRegistry.js 確認 WHEEL 已登記

如果後台已經可以用 gameType 建立活動，就不用寫 patch script。

## 六、玩法元件的標準 props / emit

玩法元件建議統一：

### props

- prizes
- disabled
- isDrawing
- resultPrize
- theme
- config

### emit

- draw
- animation-start
- animation-end
- select
- error

範例：

<WheelPlayBoard
  :prizes="normalizedPrizes"
  :disabled="!canDraw"
  :is-drawing="isDrawing"
  :result-prize="resultPrize"
  :theme="gameTheme"
  :config="gameConfig"
  @draw="startDraw"
  @animation-end="showResultModal = true"
/>

## 七、每個遊戲不能重做的東西

新增遊戲時不要重做：

- 結果彈窗
- 獎品展示
- 抽獎機會卡
- 活動規則
- 抽獎紀錄
- 領獎提醒
- 快速導覽
- 底部活動資訊
- 活動狀態提示
- 分享加次數
- 活動資料讀取邏輯
- 抽獎結果標準化

這些都要共用。

- 3x3 格子

- 中間按鈕

- 扇形輪盤
- 指針
- 旋轉動畫
- 跑馬燈

### 刮刮卡

- Canvas 刮除
- 遮罩
- 刮開比例

### 翻牌

- 卡片排列
- 翻牌動畫
- 選牌限制

## 十、結論

從現在開始，新增遊戲不能再重做整套頁面。

標準方向：

共用功能：
- GameShell
- GameActivityHeader
- GameStatusNotice
- GameChanceCard
- GamePrizeShowcase
- GameRulesPanel
- GameResultModal
- GameDrawLogs
- GameClaimInfo
- GameQuickNav
- GameFooterInfo
- useGameActivityCore
- useGameDrawEngine
- gameRegistry

遊戲專屬：
- PlayBoard 玩法元件

這樣 Multi Game Platform 才會真正變成可擴充的多遊戲平台。
